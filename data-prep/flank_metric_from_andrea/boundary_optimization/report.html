Optimizing TR Locus Boundaries via Reference-Purity Metrics

Where should a short-read STR locus definition stop extending into its flanking sequence?

Generated 2026-07-30 · tandem-repeat-explorer / data-prep / flank_metric_from_andrea / boundary_optimization

Summary. ExpansionHunter-bw2 already uses a 0.90 purity threshold internally to decide whether a read is "in-repeat" (section 2). Using that same threshold on reference purity — extend a locus boundary until the purity of the whole resulting region drops below 0.90 — is empirically justified (two independent real-data analyses across 28,616 and 578,299 loci both show purity monotonically predicts genotype concordance, section 5). Real HG002 reads give a genuinely mixed but net-positive confirmation (section 8): one locus (C9ORF72) stays confidently clean after extension, one (RUNX2) goes from a real wildcard-motif bug to a clear improvement, and two (BEAN1, RFC1) show that "purity ≥0.90" is necessary but not sufficient — CI width alone looked fine everywhere, but the underlying per-allele confidence (pOk) revealed a real trade-off at BEAN1 and showed the rule correctly declines to help RFC1's unrelated difficulty. Known disease loci recommend a notably larger extension (median 9bp) than generic genome-wide loci (median 2bp) — exactly where this kind of review is most likely to matter (section 6). One real limitation was found along the way: purity calculated naively over IUPAC-degenerate motifs (~14% of known disease loci) is unreliable and needs a targeted correction (section 9). Total Hail Batch spend: $0.0041 of the $10 budget.

1. Motivation: the EP400 problem

gnomAD's 2026-07 STR data update flagged EP400 as a case where narrowing a locus definition for catalog-consistency reasons made genotyping worse, not better:

DefinitionReference regionRepeat countOutcome
Wider (de-facto current)chr12:132062524-13206261129×CAG—
Narrower (catalog-standardized)chr12:132062548-13206261121×CAGgnomAD: "more low-quality overestimated allele sizes"

gnomAD's own words: "Although narrower, purer locus definitions often yield higher-quality ExpansionHunter genotypes, the EP400 locus is an exception." That's exactly the tension this analysis is built to resolve: too narrow a definition can be as harmful as too wide one, and the right rule needs to be about where purity actually drops, not about a fixed convention.

As a first check, we computed reference-repeat purity for the 24bp removed by the narrower definition, directly from hg38 (best-phase match against the tiled motif):

removed 24bp (8 CAG units): GCAGCAGCAGCAGCAGCAGCAACA → purity = 0.958 (23/24) kept 64bp (narrower def.): ACAGCAGCAGCAGCAGCAGCAG... → purity = 0.953 (61/64) full 88bp (wider def.): ... → purity = 0.955 (84/88)

The 8 units that the narrower definition cut off were just as pure as the units it kept — the narrowing wasn't purity-driven at all, it was a convention. A purity-based rule would never have made that cut. Section 7 works through what a purity-based rule would have recommended here, and section 8 tests it against real HG002 reads.

2. How ExpansionHunter itself defines "repetitive"

Before inventing a new threshold, we checked what threshold ExpansionHunter-bw2 already uses internally (~/code/ExpansionHunter-bw2), since any boundary rule should be consistent with how the genotyper actually classifies reads.

Read classification (in-repeat reads): ehunter/locus/IrrPairFinder.hh classifies a read pair as "in-repeat" (fully repetitive, used for the flanking-vs-spanning-vs-IRR read model) via a WeightedPurityCalculator (ehunter/core/WeightedPurityCalculator.cpp): the read is scored against every circular rotation of the motif and its reverse complement; matches score +1, transitions (purine↔purine / pyrimidine↔pyrimidine mismatches) score +0.5, transversions and N score −1, normalized by read length. The read is called in-repeat if this weighted score is ≥ 0.90 (purityCutoff_).
Reference-repeat purity (the metric relevant here): a simpler, non-weighted metric — computeRepeatSequencePurity() in ehunter/core/RepeatPurity.cpp — does a flat, gap-free, phase-anchored comparison (sequence[i] vs motif[i % motif_length], no rotation search, upper-cased, N always mismatches) and reports matched/total bases. This is exactly what populates the ReferenceRepeatPurity column already present in the existing 2–6bp flank-metrics catalog in this directory, and it's the convention this analysis builds on for the "full-region" purity metric below.

Takeaway: ExpansionHunter's own read classifier already treats 0.90 purity as the line between "repetitive" and "not repetitive" for a read. That's a natural, already-validated anchor value to test as a boundary-extension threshold, rather than picking one arbitrarily — and it's the primary threshold used throughout this report.

3. Metrics implemented

All metrics are computed as a function of offset = distance (bp) from the current annotated boundary, independently for the left and right flank (boundary_metrics.py). Two views are computed for purity, because they answer different questions:

  • Local flank purity — purity of just the newly-added flank segment [boundary, boundary+offset), compared to a perfectly phased tile of the motif. Answers "is this specific candidate extension itself repeat-like?" Noisy at very small offsets (1–2bp; a single base is either 0% or 100% "pure").
  • Full-region purity — purity of the whole resulting locus (existing core + extension), matching ExpansionHunter's own ReferenceRepeatPurity convention. Naturally smoothed by the existing core length, more robust as a decision rule, and directly comparable to the empirical purity-vs-quality relationship in section 5. This is the metric used for every boundary recommendation in this report.
  • Linguistic complexity (image-specified) — ratio of distinct 3-mers in a 24bp sliding window to the maximum possible (0 = perfectly repetitive, 1 = maximally complex).
  • K-mer Jaccard similarity (image-specified) — Jaccard index between the 24bp window's 3-mer set and the tiled motif's 3-mer set.
  • Hamming distance (custom, user-requested) — raw mismatch count between the flank segment and a perfect motif tile (the complement of local-flank purity, in raw base units rather than a fraction).
  • DP edit distance (custom, user-requested) — Levenshtein distance between the flank segment and a perfect motif tile, computed via a single O(offset²) DP table per side per locus (the standard property that dp[i][i] gives the cumulative distance at every prefix length means one table yields the whole curve, instead of O(offset³) from re-running DP at every offset). More robust than purity/Hamming to a single real indel in the repeat, which shifts the phase for every downstream base under a flat positional comparison.

5. Does reference purity actually predict genotype quality? (real data)

Before trusting a purity-based rule, we tested whether the existing reference-repeat purity of a locus (no boundary changes at all) actually predicts real genotyping quality — using ExpansionHunter-bw2's own truth-set comparison tables (real short reads vs. assembly-derived truth genotypes), joined by LocusId. Two independent analyses, run separately:

5a. 2–6bp motif catalog × 2 samples (HG002 + HG00438)

Joining the existing TR_catalog_2_6bp_with_flank_metrics.tsv.gz catalog's ReferenceRepeatPurity against both samples' truth-comparison tables (28,616 joined TruthSet loci with an EH call):

Monotonic across every bin: concordance nearly doubles (40.8%→73.8%) and mean genotyping error falls by 4.7× (9.58→2.04 repeat units) from the lowest to highest purity bin. No loci below 0.80 purity appear in this catalog at all — the 2–6bp TRExplorer detection process itself effectively filters out very impure "repeats" at intake, so this view only covers the 0.80–1.00 range.

5b. All motif sizes, genome-wide, HG002 only (578,299 loci)

A second, independent computation (purity computed fresh from hg38 with best-phase rotation search, not reused from any catalog) across every motif size, using purity bins matching the existing convention in benchmark_on_truth_set_v2/make_purity_plots.py:

Same monotonic story at full genome scale and across all motif sizes: exact-match rate rises 12× (5.5%→66.1%), discordant rate falls 4× (85.9%→20.9%), and mean signed error shrinks from a huge −47.6 repeat-unit underestimate (dominated by long, complex, low-purity regions where the reference annotation itself is a poor description of the true repeat) to essentially unbiased (+0.35) in the purest bin.

Restricting to IsPureRepeat==True loci only (removing the "known interruption" confound) shows the same broad trend but with more noise in the lowest bins (n=31–141 there) — see data/hg002_purity_vs_accuracy.summary_pure_only.tsv.

Conclusion: reference purity is a real, substantial, monotonic predictor of genotype quality in two independent real-data analyses. That justifies using it as the basis for a boundary-extension rule, and supports anchoring the rule at ExpansionHunter's own 0.90 cutoff (section 2) as a reasonable default rather than an arbitrary choice.

6. Boundary drop-off curves across the three tiers

Full-region reference-repeat purity (EH's ReferenceRepeatPurity convention) vs. distance from the current boundary. Known disease loci (blue) stay above 0.90 far longer than generic same-motif or genome-wide loci -- a genuine, non-obvious difference, not an artifact.

Local (added-segment-only) purity is dominated by single-base noise at small offsets and never stabilizes near 0.90 in aggregate -- this is why full-region purity, not local purity, is used as the decision rule.

DP edit-distance-derived identity shows the same clean separation as full-region purity, more robust to single indels.

Flat and noisy across the whole 300bp window for all three tiers -- no clean 'knee', so this metric alone doesn't support setting an extension threshold (it's more useful as a broad locus characterization).

Also flat and low throughout -- most flanking DNA simply doesn't share much 3-mer content with a short motif regardless of distance, so like linguistic complexity this doesn't give a sharp threshold.

Two plausible explanations, not mutually exclusive: disease loci were mostly defined years ago by manual/PCR-era curation without today's purity tooling, so some are more conservatively (narrowly) drawn than an algorithmic catalog like TRExplorer v1 already is by construction; and/or large, highly mutable repeat tracts (the kind that cause disease) may sit in genomic neighborhoods that are themselves more repeat-tolerant. Either way, it means disease loci are exactly where this kind of purity-based boundary review is most likely to matter.

7. Case study: EP400 revisited

Applying the full-region-purity ≥0.90 rule (section 2) to EP400's wider boundary, rounded down to whole CAG units so the extended LocusStructure stays well-defined:

SideFirst offset where full-region purity < 0.90Safe extensionUnit-aligned (3bp/unit)
Left8bp7bp6bp (2 units)
Right8bp7bp6bp (2 units)

So the purity-0.90 rule recommends chr12:132062518-132062617 (33×CAG) — further out than gnomAD's current "wider" definition, and nowhere near the narrower one. That's a direct, quantitative answer to "was the wider boundary actually justified, and by how much": yes, and there's a specific, purity-grounded amount by which it could go even wider before the flank stops looking like a repeat.

Real-read confirmation of all three definitions against HG002 (section 8 has the full methodology):

All three definitions produce a zero-width CI on HG002 for this particular sample — the genotype values differ because each definition counts repeat units against a different reference denominator (a 21× call from the narrower definition and a 29× call from the wider one describe the same physical DNA). What's notable is that extending only 2 units (6bp) past the wider boundary shifted the fitted genotype by 5 units, not 2 — boundary placement doesn't just shift the count by a fixed offset, it changes which reads the graph aligner treats as spanning vs. flanking, so a modest, purity-justified extension can move the estimate more than naive base-counting would suggest.
CI width alone makes all three look equally solid, but pOk tells a more calibrated story: it's highest at the narrower boundary's allele 1 (0.92) and lowest at purity90 (0.72–0.73, alongside elevated MeanDeletedBasesWithinRepeats, 5.4 and 2.5 vs. 0 for "current"). That's consistent with purity90 sitting right at the edge of the 0.90 knee (offset 8bp, section 1) rather than comfortably inside it — evidence the 0.90 threshold is calibrated close to where quality genuinely starts to soften, which argues for treating it as a ceiling to stop at, not a target to eagerly extend all the way to. The "current" wider definition (purity 0.954, well clear of 0.90) remains the best-supported choice of the three on this read; purity90 quantifies how much further extension the data can tolerate, not necessarily an improvement in itself.

8. Small-scale Hail Batch validation (real HG002 reads)

To go beyond reference-only analysis, we ran ExpansionHunter-bw2 (the actual C++ binary, prebuilt from this repo) via Hail Batch against real HG002 short reads (gs://str-truth-set-v2/raw_data/HG002/illumina/HG002.pcr_free.cram, cloudfuse-mounted so only the ~11 tiny target regions are read, not the whole genome), on a small catalog of 5 loci × their current and purity-0.90-recommended boundary variants — one EH invocation genotypes the whole catalog in a single job.

CI width and pOk can disagree, and that matters for how to read this table. ExpansionHunter's reported confidence interval can stay tight (even zero-width) while the underlying per-allele pOk metric — and MeanDeletedBasesWithinRepeats, which flags apparent indels inside the called repeat — show real degradation. Judged by CI width alone, BEAN1's and RFC1's purity90 variants would look "just as clean" as their current definitions; judged by pOk, BEAN1 shows a genuine confidence cost for its extension and RFC1's already-poor allele-2 confidence gets worse, not better. Only C9ORF72 and RUNX2 (naive→corrected) show the extension unambiguously helping on both signals at once.

Four distinct outcomes, all informative, none a uniform "purity90 wins": C9ORF72 is the cleanest case — a high-confidence current call and an equally high-confidence extended call, genotype shift tracking the added unit exactly. BEAN1 is genuinely mixed: the boundary was leaving real repeat-like content out (the genotype shift tracks the extension in magnitude, and reference purity of the extension itself is respectable at 0.863), but the extended call's lower pOk and non-zero deleted-bases count suggest the added TAAAA units aren't a perfectly clean continuation on these particular reads — plausibly the well-documented TGGAA/TAAAA interruption complexity at this SCA31 locus. RFC1 shows the method correctly declining to manufacture an improvement for a locus whose real difficulty (extreme motif heterogeneity across AAAAG/AAAGG/AAGGG/etc.) isn't a boundary artifact — and by the pOk signal, the small purity-driven extension here is mildly counterproductive, not neutral. RUNX2 directly demonstrates the wildcard-motif failure mode from section 9: the naive extension is worse on both CI and pOk than either the original boundary or the corrected extension, and the corrected extension is a real (if partial) improvement over naive — but RUNX2 remains a modest-confidence locus even at its best, a reminder that a boundary fix bounds one source of error, not all of them.

9. A discovered limitation: degenerate (IUPAC) motifs

10 of the 73 known disease loci use an IUPAC-degenerate repeat unit containing a wildcard position (ARX_1/2, FOXL2, HOXA13_1/2/3, PHOX2B, RUNX2, SOX3, TBX1, ZIC2 — all "GCN"/"NGC" polyalanine-expansion loci; RFC1's "AARRG" has two degenerate positions but wasn't affected here, see below). The naive purity calculation treats a wildcard motif position (N, or IUPAC codes like R) as an automatic match against any base — correct for judging whether the annotated repeat is pure, but wrong for judging a flank extension: any random, non-repetitive downstream sequence gets a "free" match at every wildcard position, inflating purity by roughly 1/motif_length per wildcard regardless of whether that sequence is really repeat-like.

RUNX2 (GCN, one wildcard in 3 positions) makes this concrete. Its right flank immediately past the core:

core (14 codons, 100% pure): GCG GCG GCG GCG GCT GCG GCG GCG GCG GCG GCT GCG GCG GCG right flank, in frame: GCA GCT GCA | GTG CCC CGG TTG ... \_genuinely Ala-coding_/ \_not repeat-like_/

The first 3 codons (9bp) really are additional alanine-coding sequence — a genuine, biologically plausible continuation of the polyalanine tract. From codon 4 onward, the sequence is not repeat-like at all, but because every 3rd base auto-matches the N wildcard, the naive full-region purity doesn't cross below 0.90 until offset 22 (7 units) instead of offset 19 (6 units) — one full codon of "free" credit from the wildcard.

CalculationRight-side crossing (first offset <0.90)Recommended extension
Naive (wildcard = auto-match)22bp21bp (7 units)
Corrected (wildcard positions excluded from num. & denom.)19bp18bp (6 units)

Only a one-codon difference in the recommended boundary — but section 8's real-read result shows it's the difference between a clean, tight-CI genotype (corrected: 17/23) and a visibly worse, wide-CI one (naive: 20/39). boundary_metrics.py itself has not been changed to exclude wildcard positions from the aggregate tier1–3 analysis in sections 5–6 (that would mean reprocessing all three tiers); the fix demonstrated here is a targeted, locus-by-locus correction. Any of the ~14% of known disease loci with a degenerate motif should have its purity-based recommendation re-checked with wildcard positions excluded before being trusted.

Practical rule: for any motif containing an IUPAC wildcard code, exclude those positions from both the numerator and denominator of the purity calculation before using it to recommend a boundary extension. Treating a wildcard as an automatic match systematically overshoots.

10. Recommendation

Use full-region reference-repeat purity ≥ 0.90 (ExpansionHunter's own IRR-read cutoff) as the default boundary-extension rule, applied symmetrically but independently per side, rounded down to a whole number of motif-length units. Concretely: starting from the current annotated boundary, extend each side outward one base at a time; stop at the last offset where the purity of the whole resulting region (existing core + everything added so far) is still ≥0.90; round down to the nearest full repeat unit.
  • Anchored, not arbitrary: 0.90 is already how ExpansionHunter classifies a read as "in-repeat" internally (section 2) — using the same threshold for the locus definition keeps the boundary consistent with how the genotyper actually treats reads near that edge.
  • Empirically justified: two independent real-data analyses (section 5, 28,616 and 578,299 loci) show reference purity is a strong, monotonic predictor of genotype concordance and error magnitude — not just a plausible-sounding heuristic.
  • Validated on real reads, with an honest caveat: the 0.90 rule recommends a boundary close to (moderately past) gnomAD's own "wider" EP400 definition. Real HG002 reads confirm the rule clearly fixes a real bug (RUNX2's wildcard-motif over-extension) and holds up cleanly at C9ORF72, but at BEAN1 and EP400 itself the extension shows a genuine confidence trade-off (tight CI, lower per-allele pOk) rather than an unambiguous win — treat 0.90 as a well-justified ceiling, not a threshold that guarantees improvement every time it's reached (section 7–8).
  • Guard against degenerate motifs: exclude IUPAC wildcard positions from the purity calculation before trusting a recommendation (section 9) — applies to ~14% of known disease loci.
  • Not a universal fix: RFC1 (section 8) shows the rule correctly does nothing useful for loci whose difficulty isn't a boundary problem — it's a targeted correction, not a guarantee of clean genotyping everywhere.

11. Limitations & follow-ups

  • IUPAC wildcard motifs (section 9) need the corrected purity calculation applied locus-by-locus; the tier1–3 aggregate curves and threshold table use the naive (uncorrected) calculation throughout, so any locus-level "recommended extension" pulled from those tables for a degenerate motif should be re-derived with the correction first.
  • Compound / multi-region loci (e.g. PRNP, HTT, CNBP, ARX — loci whose ReferenceRegion in KnownDiseaseAssociatedLoci_July2024.json is a list of adjacent-but-different repeat regions) were represented by only their first sub-region in tier 1; a single region's "flank" can actually be the start of its neighbor's real repeat, which would overstate how far the boundary should extend. PRNP was excluded from the small-scale validation set for exactly this reason after its 106bp "purity holds" signal turned out to be its second octapeptide region, not evidence of a genuinely under-extended boundary.
  • Hail Batch validation is a proof of concept, not exhaustive: 5 loci, 1 sample (HG002), 300bp search window. The gs://str-truth-set-v2/raw_data/HG00438/illumina/ path referenced elsewhere in this codebase doesn't actually exist, so a planned second-sample cross-check wasn't possible without sourcing another CRAM; only ~$0.004 of the $10 budget was used, leaving ample room for a broader multi-sample, multi-locus follow-up run.
  • Tier 2/3 sampling is capped (150 loci/canonical-motif for tier 2, 20,000 loci stratified-by-motif-length for tier 3 out of 4,863,041 total) for tractability; both are seeded (42) for reproducibility, but a full-catalog run would give a more complete picture of the tail.
  • No true independent truth exists for the small-scale validation loci beyond EP400 (which has gnomAD's own qualitative "worse" finding to compare against) — the C9ORF72, BEAN1, RFC1, RUNX2 comparisons rely on EH's own confidence/CI-width signal (before vs. after) rather than an external ground truth, since none of them happened to fall in the locally available HG002/ HG00438 truth-comparison tables at their exact modified coordinates.
  • Edit-distance and Hamming metrics (section 3) were computed for all three tiers but aren't yet summarized into a threshold table the way purity is (section 6 focuses on purity, linguistic complexity, and k-mer Jaccard) — the raw curves are in data/tier{1,2,3}.profiles.pkl for further analysis.
